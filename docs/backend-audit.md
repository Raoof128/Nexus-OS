# Backend audit (Haiku workflow, 2026 docs)

Date: 2026-11-08 · Branch: `feat/windows7-aero-redesign` · Workflow run `wf_a3426eb1-d2f`

## Method

Every agent ran on Haiku 5.5 (948 agents). The 26 backend files plus the Dockerfile, `.env.example`
and `pyproject.toml` were split into 19 units with separate file ownership, each unit owning its
tests. Per unit:

1. **Audit.** One agent read every line and checked it against the installed library source in
   `backend/venv/lib/python3.12/site-packages` (Litestar 2.25, Pydantic 2.14, supabase 2.34,
   google-genai 3.0, PyJWT 2.15, redis 8.1, httpx 0.28, sentry-sdk 2.74) and current docs
   (Context7, OWASP ASVS 5.0, OWASP API Top 10, RFC 9700, provider API docs).
2. **Verify.** Three skeptics tried to refute each finding: does the code really do this, is the
   docs claim true for the installed version, is the fix worth it and safe. A finding stood when
   at least two could not refute it. Three skeptic calls failed schema validation and returned
   nothing; their findings were judged on the remaining votes.
3. **Fix.** One implementer per unit fixed the confirmed findings and added tests.
4. **Review.** An independent reviewer checked the diff against the findings, ran ruff and the
   unit's tests, and fixed what it found.

The Opus orchestrator then integrated across units, checked every API contract change against the
frontend and the Cloudflare Worker, and reverted or adjusted changes that were unsafe to deploy.

## Orchestrator integration

Changes made after the workflow, because a unit could not see the whole system:

- **Cloudflare Worker forwards `X-Requested-With`** (`worker/index.js`). The new backend CSRF check
  rejects cookie-authenticated POST/PUT/PATCH/DELETE, `/auth/refresh` and `/auth/logout` without
  `X-Requested-With: XMLHttpRequest`. The frontend always sends it, but the Worker forwarded only an
  allowlist that did not include it, so production would have answered 403 to every mutation and to
  the silent token refresh. CORS `allow_headers` now lists it too (local dev preflight).
- **Client IP for auth rate limits: rightmost-untrusted reverted to leftmost** (see the deferred list).
- **Email account status.** The `email_inbox` migration only allows `connected`/`disconnected`, but
  the OAuth callback wrote `active` and the poller read only `active` (pre-existing). The callback
  now writes `connected`; the poller reads `connected` and legacy `active`.
- **AI draft** was broken before this audit: the compose window sent `{accountId, replyTo, subject, to}`
  but the API requires `{email_id, instruction}`. `ComposeModal` now sends the API contract.
- **Task editor no longer erases notes it could not show.** The API now returns `null` for a note it
  cannot decrypt; the editor leaves unchanged notes out of the PATCH.
- **Tasks UI matches the new 409 rules:** Move to list is disabled for subtasks and for tasks with
  subtasks, with the reason shown. Failed task saves now show an error instead of a silent rollback.
  The clear-completed prompt says open subtasks are kept.
- **Chat:** when the AI is unavailable the API now returns 503 and stores nothing (it used to store a
  canned reply). The chat window gives the typed text back on failure.
- **Bandit:** literal bidi control characters in a regex (`schemas.py`, B613 high) replaced with
  escapes, also in the tests; four false-positive B105/B106 lines marked `nosec`.
- **Packaging:** `.dockerignore` excludes `backend/.env.*` and venvs; `.env.example` moves to
  `gemini-3.5-flash-lite`; the CLAUDE.md deploy command now syncs `README.md` and `LICENSE`, which
  the image build needs (`license-files`).

## Deploy checklist

Nothing was deployed. Before deploying this backend:

_Update 2026-11-09:_ deployed to production on 2026-11-08 (Windows 7 branch) and again on 2026-11-09
(`claude/funny-hamilton-kasc78` at `098fddd`), following this checklist; the records are in
`CHANGELOG.md`.

1. **Deploy the Worker first** (`cd worker && wrangler deploy`). Without it every cookie mutation and
   the token refresh return 403.
2. **Check production env against the new boot checks.** In non-development environments the app
   refuses to start when: `APP_ENV` is not one of development/test/staging/production;
   `ALLOWED_ORIGINS` entries are not bare `https://host[:port]` or include loopback; `SUPABASE_URL` is
   not https; `AUDIT_LOG_SALT` is shorter than 32 characters; `PASSWORD_RESET_REDIRECT_URL` is not
   https or its host is not one of the `ALLOWED_ORIGINS` hosts; `TAKEAWAY_ENCRYPTION_KEY` is missing
   or not valid Fernet; `SUPABASE_SERVICE_ROLE_KEY` is missing while OAuth is enabled;
   `TRUSTED_PROXY_IPS` has a malformed entry; `EMAIL_POLL_INTERVAL_SECONDS` is below 10.
3. **`WEB_CONCURRENCY` must be 1** (or unset). The container exits otherwise, because the email poller
   and in-memory rate limiter are per process.
4. **Sync `README.md` and `LICENSE`** to `/opt/nexus/` (CLAUDE.md command updated).
5. **Gemini model.** The code default is now `gemini-3.5-flash-lite` (Google routes
   `gemini-2.5-flash` there from 2026-12-01; checked on Google's deprecations page). If production
   pins `GEMINI_MODEL`, update it. Live Gemini calls were not tested.
6. **Microsoft accounts** get `User.Read` added to the consent scope; existing connections keep
   working, new connections show it on the consent screen. OAuth flows started before the deploy
   fail once with 'Malformed OAuth state cookie' (state cookie format changed).

## Behaviour changes visible to users

- Gmail delete moves to Trash (recoverable) instead of deleting permanently.
- Logout signs out this device only (Supabase scope `local`), not every device.
- Auth outages return 503 instead of 'Invalid credentials'. The frontend still signs the user out
  if a refresh fails for any reason, as before.
- Chat history returns the newest 200 messages (`limit`, max 500); there is no load-older control yet.
- Unknown request keys are rejected (400) on task and email bodies; unsupported RRULE parts
  (COUNT, DTSTART, BYSETPOS, HOURLY and finer) are rejected; recipients with non-ASCII local parts
  are rejected.
- Every API response carries `X-Request-ID` and, unless the route sets one, `Cache-Control: no-store`.
- 429 responses carry `Retry-After`.
- `/schema` and Swagger are served only when `APP_ENV=development`.

## Deferred and open items

- **Rightmost-untrusted `X-Forwarded-For`.** Needs the real production hop list (Cloudflare edge,
  Worker subrequest, Cloudflare in front of `api.home-notes-app.uk`, nginx) in `TRUSTED_PROXY_IPS`.
  An attacker who reaches the droplet directly can still choose the leftmost entry.
  _Update 2026-11-08 (final audit):_ now available as opt-in `CLIENT_IP_STRATEGY=rightmost`
  (default stays `leftmost`); see `docs/operations.md` for the two safe production setups.
- **`CrossSiteRequestMiddleware`** (Origin / Sec-Fetch-Site check) is written and tested in
  `security.py` but not registered. It needs the Worker to forward `Origin` and `Sec-Fetch-Site`,
  and production `ALLOWED_ORIGINS` to contain the site origins. The auth routes' own Origin check
  is inert in production today because the Worker does not forward `Origin`.
- **`security_exception_handlers`** (security headers on routing 404/405) not registered.
- **Blocking calls on the event loop:** JWKS fetch in `/auth/session`, sync Redis rate-limit calls in
  some handlers, RRULE evaluation in the tasks controller. Bounded by timeouts and caps now, not
  moved off the loop everywhere.
- **Recurring-task spawn is not atomic.** A transport failure after completion commits can lose the
  next occurrence; the fix is a Postgres function (a migration, not applied).
- **Graph email:** moves change the message id and the new id is not stored; label updates return
  501/502; replies are not threaded. Gmail References keep only the parent Message-ID.
- **Frontend follow-ups:** read `?email_error=` after a refused OAuth consent; do not sign out on a
  503 from refresh; load older chat messages.
- `PUT /media/{id}` does not check status against the stored type (pre-existing).
- Recipient cap: the schema allows 500, the controller 100.

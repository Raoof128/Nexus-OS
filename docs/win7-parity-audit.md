# Windows 7 parity audit (Haiku workflow)

Date: 2026-11-08 · Branch: `feat/windows7-aero-redesign` · Audit run `wf_ca36f0e1-7e8` · Fix run `wf_cdfae0bd-b71`

## Method

**Audit.** Every agent ran on Haiku 5.5. 16 read-only auditors each took one area and compared the code
with two references: the 7.css source (`node_modules/7.css/dist/gui/*.css`, `7.scoped.css`, the upstream
repository) and the Windows 7 UX Interaction Guidelines. Findings were deduplicated by file, line and
category. Then three skeptics each tried to refute every finding from a different angle: (1) does the
code really do this, (2) is the reference true, (3) is it deliberate or trivial. A finding stood only
when at least two of the three could not refute it.

**Fixes.** Pass 1: the Opus orchestrator fixed 26 defects after re-reading the code. Pass 2: 11 Haiku
implementers each owned a separate set of files, and each was followed by an independent Haiku reviewer
who verified every finding from the code and fixed what it found. The orchestrator then did the
cross-area integration (anything that needed a file another agent owned), updated the end-to-end specs,
and reviewed every screen in a browser.

## Partial and kept items

These are the honest gaps. Everything else in the table below is fixed.

- **#5 (medium) Every focused push button pulses and stays blue after a mouse click**: Kept (7.css parity). 7.css pulses every focused push button; on Windows 7 the focused button becomes the default.
- **#38 (medium) File Manager command bar lacks Organize menu**: Partial. Organize menu added (Rename, Delete, Select all, New folder, New file, Import). Views control omitted on purpose: the list has one layout, so a toggle would do nothing. Rename and Delete also remain as per-row controls until removed in finding 124.
- **#49 (medium) Logon password field has a show/hide reveal button Windows 7 does not have**: Kept (deliberate). Reveal control kept for accessibility and to help people check what they typed (as the orchestrator directed). It remains a small w7-toolbtn with type=button, a dotted focus rectangle and an aria-label that switches between Show and Hide password. It is used on the logon and lock password boxes. The design doc should record this as an accepted difference (docs/win7-design-system.md is not owned by this agent).
- **#54 (medium) Touch and hit targets fall below the design contract on mobile and in the tray**: Partial. On pointer:coarse the tray button becomes 40x36, the Show desktop hit area 44px, and the visible strip stays 4px. Desktop hit area is 24px. Task buttons are 36px tall, and 44px needs a 48px taskbar. That also needs TASKBAR_HEIGHT in windowStore.js and Window.jsx, which I do not own, so the touch height shortfall stays open.
- **#76 (low) Loading indicators mix a lucide spinner with the 7.css marquee; 7.css spinner unused**: Partial. Tasks now uses the 7.css marquee progress bar in the same markup as ChatApp (role=status wrapper, progressbar with aria-label, 12px text). Other apps still use the Loader2 spinner (Email, FileManager, Library, Aion, Desktop, Auth, App), so the app-wide choice is not unified. Those files are outside my ownership.
- **#77 (low) Drive import shows only a toolbar spinner with no progress**: Partial. Import shows a determinate role=progressbar with file name and count (per file, in the status strip). Byte-level progress needs an importFile progress callback in fileSystemStore, which I do not own.
- **#78 (low) Folder Date modified column shows a dash for every folder**: Partial. New folders get timestamps and folder dates come from their newest child; the two seeded folders still show a dash until something changes in them.
- **#86 (low) Flyout metrics differ from 7.css menu.css**: Partial. Matched 7.css metrics on .nx-flyout border (#0006), .nx-menuitem padding and gap (label at 32px), and the 2px separator. My group and chevron menus use 7.css ul[role=menu] directly, so they get the real gutter line. The .nx-flyout/.nx-menuitem gutter line is not added, since ContextMenu.jsx (not owned) should move to ul[role=menu] markup to get it.
- **#98 (low) Window root uses role=region instead of a window or dialog role**: Partial. Added aria-roledescription="window" on both frames, so screen readers announce it as a window. Kept role="region" with the accessible name because e2e/journeys.spec.js and e2e/shots.spec.js locate windows with getByRole('region', {name}). Switching to role=group would break those specs. The landmark exposure remains until those specs move to group. See needsElsewhere.
- **#108 (low) Notification area lacks the Win7 overflow chevron and Action Center icon**: Partial. Added a chevron (Show hidden icons, aria-haspopup=menu, aria-expanded) whose menu holds Do not disturb, and the flag icon for Action Center with a red cross when unread errors exist. There are no hidden icons yet, so the menu has one real item rather than an overflow list. Tests cover the chevron menu.
- **#111 (low) Tray count badge uses a red pill not in the Win7 palette**: Kept (deliberate). The skeptic showed #d42809 is in 7.css's close-button gradient, so the palette claim was wrong. Design system §3 sanctions count pills as w7-badge, so the hand-rolled red pill now uses w7-badge (Win7 palette). The count stays because the badge is sanctioned, and the hex is gone. The flag's red cross carries problem state.
- **#131 (low) Personalization heading differs from Windows 7 wording**: Kept (deliberate). Heading left as 'Change the visuals on your computer'. The Win7 wording includes 'and sounds', and Nexus has no sound settings, so adopting it would promise a missing feature. The only evidence for the exact Win7 string was secondary sources, and the skeptics split on it.
- **#142 (low) Status bar shows Windows/Visible/API instead of Processes, CPU and memory**: Partial. Status bar is now Processes: N (open app windows), CPU Usage: N% and JS heap: N%, and the API field moved to the Services tab. Not done as specified: there is no honest source for Physical Memory: N%. Browsers do not report system memory in use, so the third field is labelled JS heap and the tooltip says so. CPU Usage is an estimate from long tasks on this page's main thread, not whole-computer CPU, and shows — where PerformanceObserver longtask is unsupported.
- **#143 (low) Performance tab uses Chrome JS-heap terminology, not Windows memory terms**: Partial. Performance tab now has CPU usage, Physical memory (installed approx. from navigator.deviceMemory, with In use: Not reported by browsers), and Browser memory (Chrome only) with JavaScript heap labels. Each group has a 60-sample history graph, and unsupported browsers show a plain not-available message. Not done: Physical Memory Total/Cached/Available/Free figures, which browsers do not expose.
- **#149 (low) Boot splash runs after sign-in, not before the logon screen**: Partial. The post-sign-in splash is now the Windows 7 "Welcome" screen. A boot screen before the logon screen was not added (it would delay every page load).
